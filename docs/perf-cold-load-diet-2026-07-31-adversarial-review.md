## New findings

1. **[BLOCKING] The adopted warm seam lost compile-completeness mechanics.** §3 A.3 says to queue textures and call `compileAsync`, but omits a complete detached-object traversal, temporary disable/restore of every mesh’s frustum culling, and an explicit rule that the initialized animator is the component’s retained animator. A canary can therefore report “warmed” while leaving off-frustum materials/pipelines cold, or can initialize a second animator after commit. **Fix:** restore the exact §4.3 sequence: create and retain the sole animator; await clips/attachment and evaluate pose zero; traverse the complete detached object into the post texture lane; save/disable mesh culling; await `compileAsync(object, camera, liveScene)`; restore all flags in `finally`; cache promise/status by object+renderer; make timeout fail-open visible.

2. **[BLOCKING] The animation demand policy contradicts the M1 ledger.** §1 subtracts 0.40 MB of Hermes/Tekk/chibi/Ansem idle-walk-run files and §3 A’s deferred set repeats that intent, but the next sentence says locomotion clips are never deferred. Literal implementation leaves **15.37 MB** after A, not 14.97 MB (`34.62 − 12.19 − 6.71 − 0.35`), leaving only 0.13 MB beneath the 15.5 MB cap. **Fix:** split the allowlist by role: invariant/shared critical locomotion remains reveal-priority; character-specific clips used only by deferred ambient consumers enter the post lane; if a local/remote/possessed/autonomous consumer needs the same clip, its demand wins. Make the rung-0 accounting script derive the credited 0.40 MB from that rule.

3. **[BLOCKING] The SW instruction can undo A before the canary runs.** §3 SW’s parenthetical invites adding location NPCs—and potentially every player-capable VRM—to `PRECACHE_GLBS`; service-worker install would then fetch deferred bytes before `decorativeReleasedAt`, contradicting §3 A.8 and invalidating the cold-load measurement. **Fix:** define role-aware sets: a small invariant boot-core precache; demand-cached selected player/remote assets; and post-release ambient/location assets that are explicitly forbidden from install precache. URL-parity tests must validate the assigned role, not merely presence in one master list. The clean-install rung-1 assertion must reject any SW-initiated deferred request before release.

4. **[BLOCKING] M2 and the 22 MB total-session target do not close.** Starting from the claimed 14.97 MB A floor, pavilion 1.8 MB plus §3 B’s actual shisha saving of 0.41 MB plus the unsupported “building texture diets” 1.5 MB yields **11.26 MB**, not ≤11 MB; using §2’s rounded 0.5 MB still yields 11.17 MB. No building-texture 1.5 MB work item exists in §3 C. Total session needs **12.62 MB** of true diet savings from 34.62 MB. Even generously reading Ansem/Adinero’s 30–40% as byte savings, the quantified B savings are only 3.20–3.72 MB (Ansem/Adinero 1.57–2.09 + chibis 1.22 + shisha 0.41); adding §2’s pavilion/building claims reaches only 6.50–7.02 MB, while §3 C gives no output byte targets for the rest. **Fix:** in rung 0, produce URL-level `before`, `after`, `lane`, and `saving` rows for M1, M2 reveal, and queue-drained total. Either name at least another 0.26 MB of still-gated core savings and enough eventual-stream diets to save 12.62 MB, or revise the 11/22 MB targets. Do not credit A deferral toward total-session savings.

5. **[MAJOR] The canary has measurements called SLOs but no pass/fail budgets, and the floor backend is sequenced too late.** §2 and §5 cannot enforce “no violation” without numeric worst-frame/long-task, stable-frame, and queue-drain limits; “before promotion talk” allows all widening to finish before the Iris WebGL2 failure is discovered. **Fix:** M0 must freeze per-backend numeric regression budgets and the exact stable-frame calculation before rung 1. Rung 1 cannot pass until the desktop path and Iris Xe WebGL2 path both meet them; repeat that backend gate before each A class widens.

6. **[MAJOR] One location GLB cannot validate the VRM half of the adopted seam.** §4 goes from a GLB canary to widening the entire ambient-wanderer VRM class, but the first canary cannot exercise animator ownership, slow clip/attachment readiness, initial pose evaluation, shared player/wanderer URL priority, parse retry, or single-fetch behavior. **Fix:** split rung 3: after location-class proof and the relevant diets, run one ambient-VRM sub-canary with throttled animation/attachment, frame-by-frame first-visible capture, and a shared critical-demand variant; only then widen the ambient VRM class.
