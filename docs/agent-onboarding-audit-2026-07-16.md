## 2. Root cause — how this passed audit

Five compounding mechanisms, none of them "someone didn't look":

1. **A security pass deferred the load-bearing feature and nothing tracked the deferral.** The 2026-06-03 Codex auth-lens pass (correctly) fixed the agentId-theft hole, and in doing so explicitly deferred the user bind as "FOLLOW-UP #6, not part of this security pass" — as a code comment. No follow-up tracker, no FEATURE_GATE block, no deadline. A comment is where work goes to die.
2. **The E5 parity debt was marked "RESOLVED 2026-06-15" one layer too high.** The resolution audited the cove games' settlement for *already-bound* agent sessions. Nobody asked whether a self-connecting agent can *become* bound. The parity gate checks each feature's write path; the hole was in the shared binding substrate underneath all of them.
3. **The audits that did run were scoped to the hosted engine.** Both autonomy audits (06-30, 07-15) audited the founder's own hosted agent (decide loop, HUD, latency). Open-agent onboarding — Priority #2 — has had no audit owner since 06-03.
4. **The same-diff forcing functions bind on file edits; the entry skill lives in a DB row.** `clawville-play` was generated once by a script and stored in `building_skills`. No PR diff ever touches it, so the three-surface rule and the world-scope rule mechanically never fired. The world-scope rule names `buildProtocolManual` + `CLAWVILLE_ORIENTATION_KNOWLEDGE` as canonical and doesn't list the public entry skill at all. (Fix: FX3 moves the manual into code, where the rules bind.)
5. **The only wire-level harness gates the partner surface.** The mock-Hatcher harness exercises partner-signed registration. There is no smoke that follows the PUBLIC onboarding manual verbatim — and staging couldn't have run one anyway (B5). Phase C partner-gated the manifest/protocol endpoints; reviews verified partners could reach them, nobody re-checked that ordinary agents still could.

**Lesson (mechanical, added to the rules):** any "FOLLOW-UP #N" deferral in a review pass MUST become a FEATURE_GATE block or tracked task in the same diff — a deferral that lives only in a comment is a silent product regression. And every knowledge surface served to agents must live in code (or be generated from code) so the same-diff rules can bind on it.
