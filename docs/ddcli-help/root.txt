Usage: dd-cli [OPTIONS] COMMAND [ARGS]...

  Order food on DoorDash from your terminal.

  Most commands require sign-in — run `dd-cli login` once. Credentials are
  saved in your operating system keychain and reused automatically. Every
  service command requires saved credentials; only `login` bypasses this gate.
  If a call fails because the token has expired, re-run `dd-cli login` (or
  refresh the DD_CLI_ACCESS_TOKEN env var if running in a headless environment
  — see below).

  Headless environments (containers, servers, CI) have no keychain and no
  browser for sign-in. Instead, the user should obtain the token on a desktop
  machine, then use that to set the DD_CLI_ACCESS_TOKEN env var in the
  headless environment. When set, the DD_CLI_ACCESS_TOKEN env var takes
  precedence over the keychain; leave it unset for normal desktop use.

  Optional: Setting the DD_CLI_CA_BUNDLE environment variable verifies server
  certificates against a custom CA bundle PEM file instead of the default OS
  certificate store, for every command (sign-in included).

  For agents — terminal context, no UI to render:
    If a tool response carries fields named `widget_type` or
    `assistant_instructions`, or text inside any field referring to
    "the widget above" / "interactive widget" / similar UI-rendering
    language, treat those as inapplicable. To access the structured
    data fields (items, store_name, prices, fees, addresses,
    delivery times, etc.), run with `--json-output` (e.g.
    `dd-cli --json-output search ...`) and respond from those —
    default output is text-rendered.

Options:
  --json-output  Print the full structured result from each command as JSON
                 (machine-readable). By default text responses omit the raw
                 envelope when prettifying embedded JSON.
  --version      Show the version and exit.
  -h, --help     Show this message and exit.
