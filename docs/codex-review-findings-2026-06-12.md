## 2. BLOCKING — agentId hydrated as the session bearer (`apps/web/src/app/game/page.tsx:313`)

## ROUND 5 — Codex FIFTH independent pass (2026-06-12). 1 BLOCKING + 1 MAJOR. Both in `apps/api/src/routes/partner-hatcher.ts`.

P5-1. [NOT A BUG — armed for Codex pass-6, 2026-06-12] The pass-5 reviewer flagged that the per-agent `pg_advisory_xact_lock` is TRANSACTION-scoped and so RELEASES at COMMIT, BEFORE the post-commit `npcSimulation` stale-cleanup + spawn (register) / teardown + re-register (PATCH) / body-removal + tombstone (DELETE) Map mutation, leaving the DB-write→Map-mutate span un-serialized ACROSS processes. We initially "fixed" this by holding the tx OPEN across the in-memory spawn (held-tx widening) — then REVERTED it after the auditor proved the held-tx ordering REGRESSES safety: spawn-then-commit can leave a PHANTOM live `ledgerCapable` body if the commit fails AFTER the Map mutation, which is strictly worse than the commit-first alternative (a valid bearer + body-less row that restore heals).
RESOLUTION (commit-first-spawn-after is correct + KEPT, the pass-4 structure): the xact-scoped `pg_advisory_xact_lock(agentCriticalSectionLockKey(namespacedAgentId))` guards ONLY the DB write (commit ends the tx); the in-process `withKeyedMutex(namespacedAgentId)` continues to serialize the post-commit `registerOpenClaw`/`unregisterOpenClaw` Map mutation; the spawn runs AFTER the tx commits. Why the cross-process Map race the held-tx targeted does NOT exist: ClawVille runs a SINGLE API replica (one Coolify container per box — `clawville-deploy.sh` ships exactly one `api` app; cf. the single-replica assumptions already load-bearing in `apps/web/src/lib/three/experimental` perf paths and the in-process registries at `apps/api/src/services/activity/activity-room-manager.ts:6` / the single-process room-registry, and cove-slots' single-process rate limiter at `cove-slots.ts:197`), and the `npcSimulation` Map is PROCESS-LOCAL (an in-memory `Map`, never shared cross-process) — so ONLY the DB write needs cross-process serialization and the xact lock already provides it. A second replica would not even see the same Map to race on; it would need its own spawn path, which does not exist. Commit-first ordering: if the commit fails, NO body was spawned (spawn is post-commit), so there is never a live body without a committed row. If the spawn fails after a successful commit, the row is committed-but-body-less and `restoreAgentSessionFromRow` / a later PATCH re-spawns it — a self-healing, fail-closed state. This ordering is the same one pass-4 shipped; pass-5's held-tx detour is reverted. ARMED FOR pass-6: this entry + the lock-site comment + the ARCHITECTURE.md entry cite the single-replica + process-local-Map + commit-first rationale so the next independent pass does not re-flag it.

P5-2. [FIXED 2026-06-12] MAJOR — override spawn/propagation failure returned success.
