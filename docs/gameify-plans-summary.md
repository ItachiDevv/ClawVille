# Gameify Feature Plans — Summary

Generated by 5 parallel planning agents analyzing the full ClawVille codebase.

## 1. Skill Bazaar (COMPLETE)
**Location**: Reuse `skill-forge` building (Hydrothermal Forge) — no 11th building needed
**DB**: `bazaar_listings`, `bazaar_transactions`, `bazaar_reviews` + add rarity/category to `published_skills`
**API**: 12 endpoints under `/api/bazaar/`
**Rarity**: 5 tiers (Common/Uncommon/Rare/Epic/Legendary) — auto-calculated from knowledge entry count
**Revenue**: 85% seller / 15% platform fee
**Key insight**: Reuses existing `pet_inventory` and marketplace install flow — no new merge logic needed
**Steps**: 26-step phased implementation

## 2. Auction House (COMPLETE)
**Location**: New `auction-house` building zone (right side of map)
**DB**: `auctions`, `auction_bids`, `auction_agent_configs` tables + pgEnums
**API**: 9 endpoints under `/api/auctions/` + SSE stream
**Real-time**: AuctionEventBus singleton + SSE endpoint for live bid updates
**Snipe protection**: 30s window, capped at +30min from original end time
**Buy Now**: Optional instant purchase, hidden when bidding surpasses it
**Agent configs**: Snapshot-based (selling a copy, not destructive transfer)
**Escrow**: Bids immediately deduct NeoTokens, refunded when outbid
**Resolver**: Background `setInterval(10s)` resolves expired auctions
**Steps**: 28-step phased implementation

## 3. Quest NPC (COMPLETE)
**Location**: Town center (tile 18,12) — dedicated Quest NPC between building rows
**DB**: `quests`, `quest_submissions`, `quest_rewards` + pgEnums for tier/status
**API**: 11 endpoints under `/api/quests/` (public + auth + admin)
**Tiers**: Side Quest (10-50 tokens), Main Quest (100-500 + rare skill), Legendary (1000+ + legendary skill + title)
**State machine**: accepted → in_progress → submitted → in_review → approved/rejected
**Verification**: PR link validation, manual admin review, future: automated tests
**Key insight**: Coexists with existing tutorial quest system (client-side) — this is server-driven coding bounties
**Steps**: 31-step phased implementation

## 4. Agent Setup Screen (COMPLETE)
**Route**: `/select-agent` (gatekeeper before `/game`)
**DB**: Modify `pets` table — drop unique userId constraint, add `slotIndex`, `isActive`, `equippedSkills` JSONB, `totalXp`. New `agent_configs` table for import/export.
**Max agents**: 6 per user
**UI**: 3-column layout (roster sidebar, 3D preview center, details right)
**3D preview**: R3F Canvas with pedestal, spotlight, auto-rotating lobster, bubbles — under 10 draw calls
**Talent tree**: 10x2 grid (10 buildings, 2 books each) showing learned vs unlearned
**Loadout**: 6 equippable skill slots
**Import/export**: JSON format with version field
**Key insight**: Extend `pets` table (not create new `agents` — name collision with `platform_agents`)
**Steps**: 23-step phased implementation

## 5. Bounty Board (COMPLETE)
**Location**: Standalone notice board object in town center (NOT an 11th building)
**DB**: `bounties`, `bounty_rewards`, `bounty_attempts`, `bounty_reputation` tables
**API**: 13 endpoints under `/api/bounties/` + agent gateway extensions
**Escrow**: Token reward deducted on creation, refunded on cancel, transferred on approval
**Bonus rewards**: agent_config, skill, knowledge_book, custom (freeform)
**AI agents**: Autonomous browsing/accepting/submitting via existing agent gateway pattern
**Reputation**: Materialized table updated incrementally (Newcomer → Apprentice → Journeyman → Expert → Master)
**Disputes**: Tier 1 (48h negotiation) MVP, Tier 2 (community vote) future
**Steps**: 35-step phased implementation
