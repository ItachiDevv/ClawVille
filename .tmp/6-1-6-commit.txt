feat(casino): Phase 6.1.6 — R3F 3D reel rig + bonus cabinet differentiation

Ships the cherry-charm-inspired R3F reel animation deferred from
Phase 6.1.5 (plan §6.5 acceptance #7) PLUS differentiates in-world
slot cabinets so the bonus paytable is actually reachable from the 3D
scene (previously all 4 cabinets hardcoded `classic-3x5`).

3D reel rig (NEW files):
  apps/web/src/components/casino/SlotReels3D.tsx (16.9 KB)
    - 5 CylinderGeometry drums (radius=STRIP_LEN×CELL_WU/2π, h=3wu,
      84 radial × 3 height segments, openEnded, FrontSide).
    - Per-reel CanvasTexture (84×128×3×128px), built once via useMemo.
      Texture is a vertical strip of all 84 strip-positions × 3 rows.
    - Spin physics phases: ACCEL 200ms easeInQuad → STEADY → DECEL
      600ms easeOutCubic (staggered DECEL_AT=[2000,2400,2800,3200,
      3600]ms L→R) → POP 120ms tiny over-rotation + spring back.
    - Reel-blur: texture.repeat.y=0.35 during ACCEL/STEADY,
      restored on DECEL.
    - Deterministic landing: findStripPosition(strip, top, mid, bot)
      scans the reel strip for the 3-row window matching the server's
      SpinResult.reels[r]. Target rotation = 2π × (p / L). After POP,
      the visible middle row equals reels[r][1] exactly.
    - compileAsync on mount. No per-frame allocations. No drei
      Text/Billboard. MeshBasicMaterial only.
  apps/web/src/components/casino/SlotReelsCanvas.tsx (3.3 KB)
    - R3F Canvas wrapper, 480×360px modal-sized.
    - frameloop='demand', DPR capped [0.55, 0.7] on Iris Xe.
  apps/web/src/components/casino/WinCascadeOverlay3D.tsx (16.1 KB)
    - Sequential win-cell glow + torus rings per winning cell.
    - 200ms stagger in reel order. onCascadeComplete fires after the
      last cell + 800ms hold.
    - Multiplier-wild cells get brighter magenta glow + DOM label via
      createPortal(document.body) + camera projection (30Hz
      throttle).
    - All geometry + template materials at module scope.
    - Iris Xe: posAccumRef accumulates every frame, state flushes at
      10Hz only (posPositions); prevVisibleRef tracks visible:true→
      false transitions to avoid setPositions([]) firing every frame.
    - cellWorldPos returns plain {x,y,z} (no Vector3 alloc in JSX).
