## Verified baseline (binary inspection, this session)

- Steady-state town center = **~14 VRM avatars** (13 wandering NPCs + player) over
  **~167–188 static draw calls**.
- **5 heavy humanoid VRMs dominate the vertex/skinning budget = ~547,800 tris ≈ 71% of
  the whole town scene:** hermes-male **118,782**, hermes-female **118,304**, tekk
  **117,861**, milady-chibi **97,186**, eliza-chibi **95,712**. `phanes` renders fine at
  **39,999** tris → proves ~40k is the silhouette-safe humanoid floor at world height.
  The 8 milady-official VRMs avg ~9.5k tris (already lean).
- **Chibis carry uncompressed 2048×2048 PNGs** (milady-chibi 2.3 MB, eliza-chibi 2.1 MB)
  — the ONLY world avatars that skipped the WebP+meshopt pipeline. = 16 MB RGBA8 VRAM each.
- **CPU hot path:** `vrm.scene.updateMatrixWorld(true)` (force) runs every frame for every
  VRM at `vrm-character-animator.ts:909`; player runs the heavier unsplit `animator.update()`
  at `player-avatar.tsx:665`.
- **No steady-state per-frame instrumentation exists.** Every committed perf number is
  load-time. `__FIDELITY_FRAME_SAMPLES` is read but never written. This is THE gap.
- Far wanderers ARE frustum-culled (fattened 1.6× sphere, `arena-npcs.tsx:515`); only the
  player is guaranteed drawn+skinned every frame.

## ⭐ MEASURED RESOLUTION (2026-06-13, local Iris Xe prod bundle via CDP) — Track A shipped, baseline captured

The `__CV_VRM_FRAME_SPLIT` sampler (Track A) was built, built clean, and captured the first
steady-state per-frame numbers this project has ever had. **`/game?perf=1`, town-idle, 13 demo
VRMs (hermes/tekk/chibis included), fresh guest.** (CDP-attached Chrome adds ~50% overhead — treat
absolute FPS as relative; the ms SPLITS and triangle/draw counts are accurate regardless.)

```

VRM CPU per-frame buckets (summed across all live animators):
  mixerMs 0.17 · humanoidCopyMs 0.18 · matrixWorldMs 0.17 · skeletonFlushMs 0.06 · springMs 0.00
  → TOTAL VRM CPU = 0.585 ms/frame  (~3.5% of a 16.8ms frame)
render: drawCalls 117 · triangles 417,309 (drawn/frame) · programs 47
scene skinned geometry RESIDENT = 721,145 tris across 81 SkinnedMeshes (all visible at town center)
per-mesh top 5 = the 5 heavy VRMs EXACTLY: 118,782 + 118,304 + 117,861 + 97,186 + 95,712
              = 547,845 tris = 76% of ALL skinned geometry. Tail drops to <20k immediately.
```

**Open question #1 (C vs D) is RESOLVED by data: the frame is GPU/triangle-bound, NOT CPU-bound.**
- Track D (narrow `updateMatrixWorld`): the entire lever bucket is **0.17 ms = ~1% of frame**.
  Best-case narrowing recovers ~40% of that = **~0.07 ms/frame**. Not worth the cosmetic-anchor
  regression risk. **DEMOTED to nice-to-have / effectively dead.**
- Track C (decimate the 5 heavy VRMs ~118k/96k → ~40k): attacks the **measured** dominant cost —
  547,845 of 721,145 skinned tris (76%). Decimation → ~200k for the 5 → **~48% fewer skinned
  triangles scene-wide**, directly cutting the Iris-Xe vertex/skinning bottleneck. **PROMOTED to #1,
  measurement-backed.** Track E (chibi 2048²→1024 WebP) rides along (same 2 files).

**Revised round-2 order:** Track C (+E) is the whole headline. Track D is parked. Track B/cleanup
opportunistic. Sampler stays behind `?perf=1` (zero-cost off) as the permanent before/after gate.

## Ranked plan (tracks)

### Track A — Measurement (BLOCKS everything, build first) · rank 1
Ready-gated steady-state RAF sampler `window.__CV_VRM_FRAME_SPLIT`, extending the existing
`measureSpike`/`perf-tracker.ts:92`. Buckets: `mixerMs`, `humanoidCopyMs`, `matrixWorldMs`
(the line-909 + player-665 lever bucket), `skeletonFlushMs`, `springMs`; plus
`renderer.info.render.{calls,triangles}`, `programs.length`, live SkinnedMesh+Skeleton
count, RAF FPS avg/p10/p1, JS frame p95/p99. Gate behind `?perf=1` → **zero cost when off.**
Capture a 5-state baseline on the Iris Xe floor.
- Files: `apps/web/src/lib/perf-tracker.ts`, `apps/web/src/components/three/World3DCanvas.tsx`, `apps/web/src/lib/three/vrm-character-animator.ts`
- Team: general-purpose. Risk: lowest (read-only instrumentation).
- **Why now:** pipeline-debugging-method rule forbids cutting before measuring. `matrixWorldMs`
  vs `gl.info.render.triangles` decides the C-vs-D order.

### Track C — Geometry decimation (biggest qualitySafe GPU win) · rank 2
Offline silhouette-preserving decimation of the 5 heavy VRMs ~118k/~96k → **~40k each**
(gltf-transform/meshopt `simplify` ratio ~0.30, error ~0.01, lockBorder), shipped as
`*-lod.vrm` at bumped `?v`. Preserves single skin, single material, VRMC_vrm, blendshapes,
bone weights. **~350k fewer tris (~45% of town budget).** NOT `combineSkeletons` (reverted).
- Files: the 5 VRMs + `agent-model-registry.ts`, `asset-preload-manifest.ts`, `scripts/compress-glb-targeted.ts`
- Team: general-purpose (pipeline) + 3da-manager (in-game render QA). Risk 3 (preserve skin
  weights + morph deltas; per-asset screenshot QA + **user sign-off** before swap, Rule E4).

### Track E — Chibi texture/VRAM (combine with C) · rank 4
Re-process the 2 chibis through the existing WebP+meshopt VRM pipeline: 2048→1024 baseColor,
lossy WebP, add meshopt+quantization, preserve VRMC_vrm. **−24 MB VRAM, kills pop-in upload
hitch.** Do in the SAME re-export pass as Track C decimation (one `*-lod.vrm` = both).
- Files: `milady-chibi.vrm`, `eliza-chibi.vrm`, `scripts/hermes-pipeline/blender-vrm-finalize-with-textures.py`, registry + manifest. Risk 2.

### Track D — VRM runtime CPU · ranks 3 + 5 (+6 conditional)
- **rank 3:** narrow the per-frame `updateMatrixWorld(true)` at `vrm-character-animator.ts:909`
  (+ player path) — drop `force` so Three's dirty-flag short-circuits the static graph +
  the duplicate `Normalized_*` rig (render never reads it), OR walk only the raw bone root.
  Magnitude UNMEASURED → Track A decides if this is rank-2-worthy or rank-4. Codex-first
  under 3da-manager (Rule E3). Risk 3 — **cosmetic hat/glasses anchors are children of raw
  bones read AFTER this call**; narrowed root must cover them (2026-04-30 hat-jump regression class).
- **rank 5:** apply the mixer/spring split to the PLAYER VRM (`player-avatar.tsx:665`) →
  `updateMixerOnly` every frame + `updateSpringOnly` at 30Hz, matching the NPC path. Risk 2,
  effort S — bundle with rank 3 (same 2 files).
- **rank 6 (conditional):** throttle mixer+matrixWorld+flush to ~30Hz for genuinely-static
  idle NPCs — ONLY if Track A shows idle fraction is large. MUST gate on `group.position`
  unchanged, not just `direction==='idle'` (2026-05-18 body-stutter fix reason).
