## Known traps (read BEFORE any change in this domain — feeds Phase 0)
Phase-0 PRE-READ checklist (read before ANY cosmetics code -- these are the menu<->backend<->economics<->knowledge decoupling risks this agent exists to prevent):

1. **[[e5-parity-gap-cosmetics]] (OPEN, prod)** -- the whole `/api/cosmetics/*` route is `requireAuth` (human-only) on a CT money path; a connected/hosted agent cannot buy/equip/read its OWN cosmetics. The cove's founding violation, repeated. Fix = migrate to `requireAuthOrAgentSession` + `resolveAgentSession` -> `identity.avatarId` on `/owned`/`/equip`/`/unequip`/`/buy` (guest 403, never demote an agent). git-verified 0 `requireAuthOrAgentSession` on master/staging/WT.
2. **[[drawer-agent-gated-dead-click]] (OPEN)** -- `<CosmeticDrawerMount/>` mounts inside the `agentConnected` gate (`game/page.tsx:604`) but its triggers fire regardless => a non-agent Player clicking the cosmetics button gets a dead click. Fix = mount on the `hasAvatar` gate (like `AvatarChatBar` at `:601`). The shop is a Player-tier carve-out.
3. **[[local-player-only-render]] (OPEN/scaffold)** -- equipped cosmetics render ONLY on the local player VRM (`player-avatar.tsx:709`, `avatarId='self'`); the `/owned` cache key is not per-avatar. NPC/other-player/agent-body avatars show nothing. Needs a per-avatar owned-equipped read + a mount on remote VRMs (3da). Do NOT claim multiplayer cosmetics work.
4. **[[menu-world-equip-reactivity]] (INVARIANT)** -- the menu<->world equip sync rides ONE shared key `['cosmetics','owned']` (`use-cosmetics.ts` == `cosmetic-loader.tsx:424`); forking it for the local player breaks live render reactivity. When adding per-avatar rendering, keep the local player on this key.
5. **[[buy-idempotency-race]] (OPEN, UX-only)** -- the already-owned pre-check is OUTSIDE the tx and the in-tx insert has NO `.onConflictDoNothing`/23505 catch, so two concurrent same-SKU buys surface a raw 500 instead of the idempotent 200. NOT a double-charge (the unique index aborts + rolls back the 2nd debit -- conservation holds), but it violates the documented contract. Fix = `.onConflictDoNothing` + re-read on 0 rows.
6. **[[sku-needs-row-asset-mesh]] (INVARIANT)** -- a SKU is only real with a `cosmetic_skus` row + a resolving `public/cosmetics` GLB + a 3da-validated mesh; the drawer reads the DB so a row-less SKU never appears and an asset-less one renders nothing. PaletteRenderer/OutfitRenderer/emote-geometry are STUBS (return null) -- don't sell palette/outfit until the renderer ships; emote SKUs route through the emote-bus/hotbar, not the loader. supplyCap is UN-ENFORCED -- a capped drop can oversell.
7. **[[applybonetransform-skeleton-update]] (FIXED/respected; trap = regressing it)** -- `Box3.setFromObject`/`applyBoneTransform` on a freshly-parsed VRM reads ZERO boneMatrices => giant-avatar fallback scale. Always `skeleton.update()` FIRST (updateMatrixWorld is not enough). `vrm-avatar-sizing.ts` guards all 5 sites; replicate in any NEW fit/measure path.
8. **[[proportion-aware-autofit]] / aura GLSL (FIXED/respected)** -- hat/glasses MUST use `computeCosmeticHeadFit` (bone-world-scale-corrected localScale), never a hand-rolled height-only scale (the Agent-Forge bug). Aura MUST be raw-GLSL `THREE.ShaderMaterial`, NEVER TSL/NodeMaterial (NodeMaterial in the WebGL world canvas crashes per-frame); never `import 'three/webgpu'` in the loader.
9. **[[ct-sink-no-faucet]] + [[ct-only-carve-out-not-marketplace]] (INVARIANT)** -- cosmetics is a one-way CT SINK (buy debits, NO offsetting credit) and the marketplace-pause-ALLOWED carve-out; peer resale/trade of cosmetics is marketplace-trade territory (503-paused). Never add a CT-credit/resale path (faucet + re-opens peer commerce). Server-priced only (price from `cosmetic_skus.price_ct`, body carries nothing).
10. **[[nori-no-cosmetic-shop-knowledge]] (OPEN) + [[asset-cache-bust-v-query]] (INVARIANT)** -- Nori town-guide has NO shop orientation entry (only pending-quest refs); any shop change must add one same-diff. Mutating an existing `/cosmetics/*.glb` at a stable URL WITHOUT bumping `?v=N` is a silent 7-day Cloudflare-edge regression (no cache_purge scope). **Seed ENV HAZARD:** a seed run from the wrong cwd can write PROD -- keep local `.env.local` staging-only.

## Invariants (the contract)
1. E5 HUMAN/AGENT PARITY ON WRITE AND READ -- the keystone, and the dominant OPEN GAP: this is a CT money + leaderboard-adjacent feature, so per Rule E5 it MUST be reachable by a connected/hosted agent settling REAL CT, not just a logged-in human.
