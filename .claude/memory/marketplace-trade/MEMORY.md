## Known traps (read BEFORE any change in this domain — feeds Phase 0)
Phase-0 pre-flight — read EVERY one before writing code (anchored versions in the linked entry files). These emphasize the menu↔backend↔economics↔knowledge decoupling this agent exists to prevent: the menu must reflect the PAUSED backend, and no surface un-pauses without the others.

1. **The 503 write-gate is sacred + must stay FIRST.** Each route mounts a `use('*')` returning `503 {code:503}` for POST/PUT/PATCH/DELETE (bazaar.ts:30-43, marketplace.ts:20-33, auctions.ts:241-254); GET passes. A refactor that registers a write handler ABOVE it, relaxes the method-set, or deletes it as a 'dead stub' silently re-opens paid peer commerce. Verify on staging: `curl -X POST` a write → 503, `curl` a GET → 200. `[[the-503-write-gate]]` — PAUSED/ENFORCED.
2. **Modal CTAs point at paused writes (the menu↔backend decoupling — accidental un-pause surface #1).** auction-modal.tsx has live `api.placeBid`/`buyNow`/`cancelAuction` (729/743/1340/1356); bazaar/marketplace modals similarly. While paused these hit a 503 — a user clicking "Bid" gets an error, not a "paused" state. Branch on the `ApiError.code`/`status` (apps/web/src/lib/api.ts), never the message string, or don't surface the CTA. `[[modal-exposes-paused-write]]` — OPEN (graceful-503 not implemented; mitigated only by the modals not being surfaced in-flow).
3. **The auction resolver + SSE run UN-GATED at module load.** `auctions.ts:226 auctionResolver.start()` is a 10s setInterval that SETTLES escrowed bids via the ledger; `/stream` SSE is also un-gated. Dormant ONLY because bids 503 → nothing to resolve. Un-pause bidding and the resolver goes live instantly; to truly turn auctions OFF you must also stop the resolver. `[[auction-resolver-ungated]]` — PAUSED/LATENT.
4. **The agent buy action BYPASSES the 503 gate AND is non-transactional (pause-parity hole #2).** `packages/agent-runtime/src/actions/buy-bazaar-listing.ts` (registered actions/index.ts:40) calls `debitClawTokens`/`creditClawTokens` DIRECTLY (l.161/170), NOT via the gated route — a hosted agent can buy while "paused." Worse: debit+credit+writes run OUTSIDE any `db.transaction` with `.catch(() => {})` compensating refunds (l.234-247). Treat as protected-surface money work; align reachability with the gate + replace refunds with one tx before reactivation. `[[agent-action-bypasses-gate]]` — OPEN.
5. **Un-pause = real money path with the E5 GAP (the economics↔knowledge decoupling).** EVERY write handler is `requireAuth` (human-only) — grep returns ZERO `requireAuthOrAgentSession`/`resolveAgentSession`/`getSubject` in the domain. Un-pausing as-is locks connected agents out of a money + leaderboard feature (the exact Cove getSubject violation). Un-pause MUST add `{user,agent}` on WRITE *and* READ (`/my-purchases`/`/my-bids`/`/my-listings`) + idempotency + agent action surface (PROTOCOL bump + Codex) + adversarial audit + a PARITY note. `[[e5-parity-gap-on-unpause]]` `[[unpause-is-a-new-money-path]]` — OPEN (latent until un-pause).
6. **No idempotency anchor on the money paths.** Bazaar buy / auction bid+buy-now are race-safe via atomic status-flip + FOR UPDATE, but there is NO client `Idempotency-Key` + DB partial-unique row — NOT replay-safe under a retry storm. Add the cove pattern before this carries meaningful CT. `[[no-idempotency-anchor]]` — OPEN (latent until un-pause).
7. **FEATURE_GATE lapsed = DELETE, not extend.** The `skill_marketplace` block ("Metric: to be defined / Deadline: after the overhaul ships") is an open-ended deadline = debt. Per no-scaffolding-theater a lapsed gate is DELETED; renewal cites a NEW metric reading. Un-pausing one surface fractures the shared gate — all-or-none, founder-approved. `[[feature-gate-skill-marketplace]]` — OPEN debt.
8. **Marketplace `/buy` is FREE, bazaar `/buy` is PAID.** marketplace.ts:388 grants inventory + returns `avatar.clawTokens` UNCHANGED (zero ledger import in the file); bazaar.ts:706 debits buyer + credits seller (−15% fee). Don't "fix" the unchanged balance as a missing debit; don't assume "buy" means a CT path — check the route. `[[marketplace-free-vs-bazaar-paid]]` — fact.
9. **Cosmetic carve-out is NOT paused (the economics boundary).** The pause is PEER commerce only (`bazaar_listings`/`auctions`/`published_skills`); the first-party CT cosmetic shop (`cosmetics-shop`) is an allowed carve-out. Never pause a cosmetic or un-pause a peer listing because "both are shops" — peer-vs-first-party is the discriminator. `[[cosmetic-carveout-not-paused]]` — boundary rule.

7. GAP: there is NO client `Idempotency-Key` + DB partial-unique anchor — race-safe, NOT replay-safe across a client retry storm. Add the cove pattern on un-pause.
8. A skipped refund/settle vaporizes CT; a double-refund or double-settle mints it. The resolver's atomic claim prevents the double-settle faucet — never weaken it.
