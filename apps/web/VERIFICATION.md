## 1. Verifiable Randomness

ClawVille's reel game uses **commit-reveal HMAC-SHA256** for outcomes. The server cannot alter results after a player sees their reels.

### The algorithm

For every spin:

```
HMAC-SHA256( key = serverSeed_raw_bytes,
             message = "${clientSeed}:${nonce}:${blockIndex}" )
```

- `serverSeed` — 32 bytes of CSPRNG, generated at session open. Hidden until session close.
- `serverSeedHash` — `sha256(serverSeed_utf8_hex_string)`. Published at session open. This is the **commit**.
- `clientSeed` — 8 hex bytes generated by the server (future iterations will allow player-supplied).
- `nonce` — 0 at first spin, increments by 1 per spin.
- `blockIndex` — `floor(cursor / 32) + i`, where `cursor` is the byte offset into the HMAC stream.

The first 32 bytes of HMAC output for block 0 are the first reel's random bytes. The server samples 5 uniform integers in `[0, reelStripLength)` via rejection sampling (no modulo bias). Each sample consumes 4 bytes; cursor advances by 4 per sample.

At session close, the server **reveals** `serverSeed`. Any third party can then verify:

1. `sha256(serverSeed) === published_serverSeedHash` (commit integrity)
2. For each spin: re-derive the bytes via HMAC, re-run rejection sampling, re-evaluate the paytable → confirm the persisted reels + token payout amount.

If the server tampered with any spin, step 2 fails for that spin and the entire session is provably dishonest.

### Source files

- **Server (Node):** [`apps/api/src/services/provable-rng.ts`](apps/api/src/services/provable-rng.ts) — ~250 LOC, Node `crypto` stdlib only, **zero external runtime dependencies**.
- **Browser (WebCrypto):** [`apps/web/src/lib/casino/verifier.ts`](apps/web/src/lib/casino/verifier.ts) — same algorithm, runs in any browser, no server round-trip needed.

## 2. Long-Run Token Return Rate

**Target token return for the `classic-3x5` paytable: 96.00% ±0.5%.**

Over a long run of spins, players collectively receive back 96 tokens for every 100 spent. This is a **statistical guarantee in the limit**, not a per-session guarantee. Individual sessions vary widely.

### Empirical verification

Run the 1M-spin Monte Carlo simulator yourself:

```bash
git clone https://github.com/ItachiDevv/ClawVille
cd ClawVille
bun install
bun scripts/casino/rtp-sim.ts --spins 1000000 --predict 100
```

Output (representative, ~10s wall-clock):

```
1,000,000 spins → 95.89% (95% CI ±0.06%)
Hit frequency: ~73%
Max single-spin token return: 800× stake (5-of-a-kind Seven)
Per-symbol middle-row hit rate matches strip density to <0.02% error
```

Verified across 5 independent random seeds — all land inside `[95.50%, 96.50%]`:

| seed | result |
|------|--------|
| `a`*64 | 95.80% |
| `b`*64 | 95.96% |
| `c`*64 | 95.89% |
| `d`*64 | 96.12% |
| `e`*64 | 96.50% |

### CI gate

Every PR touching the paytable, engine, or RNG runs a 100k-spin simulation in CI. If the rate falls outside `[95.00%, 97.00%]`, the build fails. See [`.github/workflows/rtp-gate.yml`](.github/workflows/rtp-gate.yml).

### Paytable + reel strips (public)

All math constants are committed in source:

- **Symbols + payouts:** [`packages/shared/src/constants/slot-paytables.ts`](packages/shared/src/constants/slot-paytables.ts) — 10 symbols, payouts per (2/3/4/5)-of-a-kind, wild substitution rule.
- **Reel strips:** Same file — 5 reels × 84 positions. Per-symbol density determines hit frequency.

```
Cherry  22/84 = 26.19%
Lemon   22/84 = 26.19%
Orange  14/84 = 16.67%
Plum    14/84 = 16.67%
Bell     7/84 =  8.33%
BAR/Seven/WILD/BAR×2/BAR×3: 1/84 each = 1.19%
```

The simulator outputs per-symbol middle-row hit rate from real samples; it matches the analytic density to <0.02% absolute error at 1M spins.

## 3. Per-Session Verifier UI

Any player can verify their own past sessions through the in-game verifier:

- **Public verifier:** paste `serverSeed`, `clientSeed`, `nonce`, `cursor`, `predict`, get side-by-side local-vs-server reel computation. Anonymous, no auth.
- **Per-session verifier:** owner-only. Loads the full spin history, replays every spin in your browser via WebCrypto, shows green check or red flag per spin.

Source: [`apps/web/src/app/casino/verify/`](apps/web/src/app/casino/verify/) + [`verifier.ts`](apps/web/src/lib/casino/verifier.ts).

Tamper detection: if the server ever modified a persisted spin row, the verifier surfaces exactly which spin and how it diverged.

## 5. Reproducibility Recipe

To verify a specific past session is honest:

1. Cash out a session in-game. Copy the revealed `serverSeed` from the HUD.
2. Open the per-session verifier page for your `sessionId`. The page replays everything client-side. Or query the API anonymously:
   ```bash
   curl https://api.clawville.world/api/casino/slots/session/<sessionId>
   curl https://api.clawville.world/api/casino/slots/session/<sessionId>/spins
   ```
3. For each spin record, manually compute:
   ```bash
   curl -X POST https://api.clawville.world/api/casino/slots/verify \
     -H "Content-Type: application/json" \
     -d '{
       "paytableId": "classic-3x5",
       "serverSeed": "<revealed_seed_hex>",
       "clientSeed": "<from_session>",
       "nonce": <from_spin_row>,
       "cursor": <from_spin_row.cursorBefore>,
       "predict": "<from_spin_row.predict>"
     }'
   ```
4. Compare the returned `reels` and `winAmount` against the stored spin row. If they match, the spin was honest. If not, the server tampered — surface it publicly.

The verifier is **also anonymous** — any third party can run this against any other player's revealed session given the session's public ID and the revealed `serverSeed`.
